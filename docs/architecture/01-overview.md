# AI Avatar Studio V1.0 技术架构总览

> 版本：V1.0
> 状态：已冻结
> 日期：2026-09-24
> 用途：正式开发准备阶段的技术架构基线

## 1. 文档定位

本目录描述 AI Avatar Studio V1.0 从零设计的技术架构。它用于约束后续 UI/UX 设计、Task Card 拆分、工程实现和代码审核。

本架构的当前目标是先在本地开发环境跑通完整商业闭环，再根据真实测试反馈部署测试服务器和生产环境。架构按几千名用户的正式产品设计，但第一阶段不要求一次性实现所有能力。

## 2. 产品闭环

```text
邀请码进入 / 邮箱绑定
        ↓
选择生成模式、风格和 Prompt
        ↓
上传照片（按模式可选）
        ↓
创建异步任务并预留点数
        ↓
Celery Worker 调用 AI Provider
        ↓
结果进入对象存储
        ↓
成功消费点数 / 失败释放点数
        ↓
查看、下载、分享和反馈
```

## 3. 最终技术选型

| 层级 | 技术方案 | 主要职责 |
|---|---|---|
| 前端 | Next.js + React + TypeScript | SEO、公开页面、生成流程、用户中心 |
| 后端 | FastAPI + Python | REST API、认证、业务规则、事务编排 |
| 数据库 | PostgreSQL | 用户、任务、点数、订单、审计 |
| ORM 与迁移 | SQLAlchemy 2.x + Alembic | 数据访问和版本化迁移 |
| 异步任务 | Celery | AI 调用、轮询、恢复、清理 |
| 队列与缓存 | Redis | Celery Broker、会话、限流和短期锁 |
| 对象存储 | Storage Adapter | 本地 MinIO，生产 COS / OSS / S3 |
| AI 调用 | AIProvider + ProviderRouter | 隔离供应商差异 |
| 本地编排 | Docker Compose | 一键启动完整开发环境 |
| API 契约 | OpenAPI | 生成前端 TypeScript 类型与客户端 |

## 4. 架构原则

1. 单仓库管理，前后端通过 REST API 保持清晰边界。
2. Python 和 TypeScript 不强行共享代码，以 OpenAPI 共享协议。
3. Worker 与 FastAPI 使用同一套后端业务代码，通过不同进程启动。
4. 业务层禁止直接调用具体 AI 供应商。
5. 业务层禁止直接依赖 MinIO、COS、OSS 或 S3 SDK。
6. 图片生成必须异步，用户离开页面后任务仍能继续。
7. 点数变化只通过不可变流水发生，禁止直接改余额。
8. 任务状态与计费状态分离，成功、失败和人工复核均可审计。
9. 所有可能重复提交的写接口必须幂等。
10. 本地与生产只更换配置和基础设施连接，不改变业务代码。

V1.0 的正式仓库边界、服务职责、依赖方向、本地 Compose 拓扑、环境变量和日志安全规则统一见 [仓库边界与本地进程基线](./09-repository-boundary.md)。该文件是 `LEAD-01` 的冻结补充，不改变本文件及后续契约中的业务规则。

V1.0 目标目录固定为 `frontend/`、`backend/`、`shared/`、`docs/`、`docker/` 和 `scripts/`。当前仓库中的旧测试版布局不属于 V1.0 目录，也不是迁移或复用前提。

## 5. 系统边界

第一阶段包含：

- 邀请码与邮箱绑定；
- 正式点数账户和流水；
- 照片 + Prompt、纯 Prompt，以及受 Feature Flag 控制的参考图模式；
- 固定生成 2 张图片；
- 异步任务、失败重试、自动释放点数和人工复核；
- 本地与生产对象存储适配；
- 风格、Prompt 模板、生成历史、下载、分享和反馈；
- 订单数据结构预留，不实现真实支付；
- Provider 调用成本和审计记录。

第一阶段明确不做：

- 微服务拆分；
- Kubernetes；
- 多模型自动路由；
- 多机自动扩容；
- 正式支付流程；
- 用户社区、评论和排行榜；
- 视频生成；
- 复杂营销和优惠券系统。

## 6. 决策优先级

发生实现分歧时按以下顺序判断：

1. 点数和资金安全；
2. 任务幂等与可恢复性；
3. 用户数据和图片隐私；
4. API 契约一致性；
5. 本地完整闭环；
6. 扩展能力；
7. 开发便利性。
