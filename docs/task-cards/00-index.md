# AI Avatar Studio V1.0 任务卡总索引

> 日期：2026-09-25
> 状态：正式开发阶段执行基线
> 适用范围：从零实现 V1.0，不以旧测试版实现作为架构前提

## 使用方式

每个新对话窗口只处理一张任务卡。新窗口开始时，必须先阅读：

1. `docs/architecture/01-overview.md` 至 `09-repository-boundary.md`；
2. 本索引；
3. 对应任务卡；
4. 对应 API、数据库或 Provider 文档。

完成当前卡片的一个门禁后必须暂停，等待技术负责人审查。没有明确的“通过”消息，不得开始下一步、下一张卡或范围外工作。

## 技术负责人任务卡

这些卡片由主 Agent 负责，在独立对话窗口完成设计、冻结契约、审查和测试方案，不把实现工作转给国产模型：

| 卡片 | 工作 | 结果 |
|---|---|---|
| `LEAD-01` | V1.0 架构与仓库边界 | 架构基线、目录、进程和环境边界 |
| `LEAD-02` | PostgreSQL 数据库设计 | Schema、约束、迁移顺序和数据不变量 |
| `LEAD-03` | REST API 与错误码契约 | OpenAPI、请求响应、幂等和错误码 |
| `LEAD-04` | 点数账务与生成任务状态机 | 预留、消费、释放、人工复核和幂等规则 |
| `LEAD-05` | AI Provider 与 Storage Adapter 契约 | Provider、存储、成本、超时和安全边界 |
| `LEAD-06` | 测试矩阵与验收门禁 | 单测、集成、E2E、异常场景和发布条件 |
| `LEAD-07` | 国产模型代码审核与阶段放行 | 审核报告、风险清单和下一张卡授权 |

## 国产模型工程任务卡

国产模型只实现被授权的卡片。实现顺序固定如下：

| 卡片 | 工作 | 前置 |
|---|---|---|
| `ENG-00` | 工程环境和目录骨架 | `LEAD-01` 通过 |
| `ENG-01` | PostgreSQL、SQLAlchemy、Alembic 和基础迁移 | `LEAD-02` 通过 |
| `ENG-02` | FastAPI 基础服务、配置、健康检查和 OpenAPI | `ENG-01`、`LEAD-03`、`LEAD-04`、`LEAD-05` 通过 |
| `ENG-03` | 用户、邀请码、邮箱绑定和 Session | `ENG-02` 通过 |
| `ENG-04` | Points Service 和点数流水 | `ENG-03`、`LEAD-04` 通过；本轮不授权 |
| `ENG-05` | Storage Adapter、上传和媒体资源 | `ENG-04`、`LEAD-05` 通过 |
| `ENG-06` | Generation Service、Celery、Redis 和 MockProvider | `ENG-05`、`LEAD-04`、`LEAD-05` 通过 |
| `ENG-07` | PrimaryProvider 和成本审计 | `ENG-06` 通过，`LEAD-05` 复核 |
| `ENG-08` | Next.js 前端生成工作流和用户页面 | `ENG-02` 至 `ENG-06` 通过 |
| `ENG-09` | 分享、下载、反馈和生命周期清理 | `ENG-05`、`ENG-06`、`ENG-08` 通过 |
| `ENG-10` | 本地完整闭环和回归测试 | `ENG-03` 至 `ENG-09` 通过 |

`ENG-00` 的可执行步骤、允许修改范围、Compose 拓扑和停线回报格式见 [ENG-00：工程环境和目录骨架](./ENG-00-engineering-foundation.md)。

ENG-01 已按技术负责人裁决完成并收口；第 5 步不执行。本索引不因此提前授权 ENG-04、ENG-05、ENG-06 或任何其他工程卡。

## 阶段放行顺序

```text
LEAD-01
  ↓
LEAD-02 + LEAD-03 + LEAD-04 + LEAD-05
  ↓
ENG-01 → ENG-02 → ENG-03 → ENG-04 → ENG-05 → ENG-06
  ↓
ENG-07 → ENG-08 → ENG-09 → ENG-10
  ↓
LEAD-06 → LEAD-07
```

`LEAD-06` 可以在工程开发过程中提前编写测试方案，但最终验收必须等 `ENG-10` 完成。任何涉及点数、任务状态、Provider 回调或数据迁移的代码，必须经过 `LEAD-07` 放行。

## 国产模型统一停线规则

- 发现架构、契约、字段、状态或点数规则不一致：立即停止，提交问题，不自行决定。
- 需要新增文件或修改任务卡未列出的文件：停止并说明原因。
- 测试失败：停止修复当前卡片，不跳到下一张卡。
- 构建失败、迁移失败或密钥进入前端：停止并报告。
- 任何卡片未收到技术负责人“通过”消息：不得继续。
