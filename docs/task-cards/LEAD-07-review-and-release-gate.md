# LEAD-07：代码审核与阶段放行

## 会话目的

在每张工程卡完成后进行独立审核，确认实现符合契约，再明确下一张卡。

## 审核顺序

1. 检查改动文件是否在卡片范围内；
2. 检查 API、数据库、状态机和点数规则是否被改变；
3. 检查事务、幂等、权限、超时和密钥边界；
4. 阅读新增测试，确认测试验证行为而非只覆盖代码行；
5. 运行类型检查、构建、迁移和卡片指定测试；
6. 记录问题等级和修复要求；
7. 只有全部通过才发送下一步授权。

## 必须拒绝的情况

- 路由、Worker 或 Provider 直接改钱包余额；
- 没有流水的点数变化；
- 未经批准修改状态机或错误码；
- API 契约与 OpenAPI 不一致；
- 数据库变更没有迁移；
- 服务端密钥进入前端；
- 测试使用真实生产凭据或真实用户图片；
- 未通过当前卡片就开始下一张卡。

## 输出格式

```text
Task Card：ENG-xx
结论：通过 / 需修复 / 阻塞
发现：按严重级别列出文件和证据
验证：命令与结果
修复要求：明确到文件、行为和测试
授权下一步：ENG-xx 或暂停
```
